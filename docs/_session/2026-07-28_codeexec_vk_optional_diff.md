# ВК — по-настоящему необязательное поле: непонятная ссылка больше не рушит сохранение профиля

**Дата:** 2026-07-28
**Статус:** ⏳ жду 🟢 — код правлен локально, `npm run build` проходит, ничего не закоммичено и не задеплоено.
**Прод не изменён:** только два read-only `SELECT` (счёт профилей с непустым `vk`).

---

## 1. TL;DR

Задача звучала как «сделать профиль в vk необязательным полем». Проверил все
четыре слоя — **формально ВК уже необязателен везде**: колонка `profiles.vk
text DEFAULT ''` без NOT NULL, `isValidVk('')` возвращает `true`, в форме
подпись «(необязательно)» без атрибута `required`, в `utils/profileCompleteness`
поля `vk` нет ни в одном наборе обязательных.

Обязательным он вёл себя ровно в одном месте — и это не «пустое нельзя», а
«непонятное нельзя»:

> `services/dataService.js → updateUser` бросал ошибку, если в поле ВК было
> введено что угодно, что не приводится к `https://vk.me/<username>`. Падал при
> этом **весь PATCH профиля** — вместе с ВК не сохранялись имя, город, фото,
> компетенции, «что могу предложить».

`VK_RE` принимает только латиницу (`[A-Za-z0-9_.-]{2,64}`). То есть человек,
вписавший в это поле своё имя кириллицей, телефон, слово «нет» или ссылку с
пробелом, терял все правки профиля.

Отдельно неприятно: `UserApp.handleUpdateProfile` делает оптимистичное
обновление **до** запроса (`onUpdateUser(updated)`, строка 334). Поэтому на
экране новые значения появлялись, всплывал тост с ошибкой про формат ВК — и всё
выглядело как «ну, что-то с ВК не то, зато остальное сохранилось». Пропажа
обнаруживалась только после перезагрузки страницы.

Починено: непонятная ссылка ВК теперь просто не пишется в базу, прежнее
значение остаётся, остальной профиль сохраняется штатно. Форма предупреждает об
этом прямо во время ввода, до нажатия «Сохранить».

## 2. Дизайн-решения

**Почему чиню в `dataService`, а не в форме.** Слой-владелец решения «принимаем
ли значение необязательного поля» — это контракт сохранения. Форма отвечает
только за то, чтобы человек понимал, что происходит. Если бы я поставил гвард
только в `ProfileView`, тот же throw продолжил бы стрелять со страницы ведущей.

**Параллельный баг того же типа — страница ведущей.** `LeaderPageView.handleSaveReviews`
шлёт `{...leader, leader_reviews}`, то есть весь профиль вместе с `vk` из базы.
Пока throw был на месте, одна старая некорректная строка `vk` в БД блокировала
человеку и сохранение отзывов, и вообще любое сохранение профиля — навсегда, без
возможности починить это из интерфейса. Правка в слое-владельце закрывает и это.

**Сколько людей это задело в базе — проверил.** Из 61 профиля `vk` заполнен у
16, невалидных среди них **0**. Значит «вечно заблокированных» сейчас нет, и
бэкфилл не нужен. Баг бил в момент ввода, а не по сохранённым данным.

**Почему не сохраняем непонятный текст как есть.** ВК с профиля утекает на
публичную страницу ведущей и в контакты публичных встреч (`events.host_vk`,
триггер `sync_meeting_to_event` из phase22). Битая ссылка там — хуже пустого поля.

**Почему не показываю тост после сохранения.** `UserApp.handleUpdateProfile`
после успешного запроса безусловно вызывает `onNotify("Профиль сохранен")`.
Любой мой синхронный тост из `handleSave` был бы им тут же перекрыт. Поэтому
предупреждение живёт под полем и видно, пока человек редактирует.

**Что делаем с введённым текстом.** В базу он не уходит, в payload не
подставляется (иначе оптимистичное обновление покажет в профиле ссылку, которой
в базе нет), в поле остаётся прежнее значение. Формулировка подсказки говорит
об этом прямо, без «упс, что-то пошло не так».

## 4. Что НЕ затронуто

- **Telegram остался обязательным.** Его throw в `updateUser` и проверка в
  `handleSave` не тронуты — это осознанно разные контракты.
- **Правила нормализации.** `normalizeVk`, `VK_RE`, `isValidVk` не менялись —
  какая ссылка считается корректной, решается ровно так же, как вчера.
- **База.** Ни миграции, ни бэкфилла: колонка и так nullable с `DEFAULT ''`,
  невалидных значений в проде нет (0 из 16 заполненных).
- **Процент заполненности и напоминалка о профиле.** `utils/profileCompleteness`
  не трогал — `vk` там и не было.
- **Публичная страница ведущей и контакты встреч.** `LeaderPageView`,
  `events.host_vk`, триггер синхронизации phase22 — без изменений.
- **push-server.** Не задет, деплоить не нужно.

## 5. Edge-case'ы

| Что вводит человек | Что происходит |
|---|---|
| Пусто | Сохраняется пустым — очистить поле по-прежнему можно (`isValidVk('') === true`) |
| `vk.com/username` | Нормализуется в `https://vk.me/username`, сохраняется — как раньше |
| `@username` | Нормализуется в `https://vk.me/username`, сохраняется — как раньше |
| `vk.com/id123` | Остаётся `https://vk.me/id123`, сохраняется — как раньше |
| `Ольга Садовникова` | Подсказка янтарным во время ввода; профиль сохраняется целиком; в поле остаётся прежнее значение |
| `+79001234567` | То же самое |
| Один символ (`я`, `a`) | То же самое — `VK_RE` требует минимум 2 символа |
| Было корректное значение, стёрли и вписали ерунду | Прежняя ссылка остаётся в базе; правки остального профиля сохраняются |
| Сохранение отзывов со страницы ведущей при битом `vk` в базе | Раньше падало целиком, теперь проходит (в проде таких строк сейчас нет) |

   подсказка → «Сохранить» → тост «Профиль сохранен», имя и город на месте
   после перезагрузки.
